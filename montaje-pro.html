Día 0 · Prerrequisitos

Cuentas creadas y cuello de botella lanzado

Verificación de empresa en Meta — lanzar PRIMERO

Por qué primero: es lo único que no depende de ti. Meta tarda de horas a días; sin verificar, WhatsApp Cloud API se queda en modo prueba (límite de destinatarios). Si lo dejas al final, bloquea el lanzamiento.
  • Business Manager → Centro de seguridad → Iniciar verificación. Necesitas alta de autónoma/factura.
  • Crea ya un System User → de ahí saldrá el token permanente de WhatsApp.
Error típico: cuenta personal de Facebook sin Business Manager → no podrás pedir el token permanente.

Resto de cuentas + gestor de claves

  • DigitalOcean (6 €/mes) · Anthropic (pago por uso) · Resend (gratis) · Bitwarden (claves).

Semana 1 · Cimientos

n8n productivo con HTTPS que sobrevive a un reinicio

Crear y blindar el VPS

Por qué: el cerebro corre 24/7 aquí. Sin firewall ni usuario no-root es un riesgo.
# Droplet: Ubuntu 24.04 · 1 GB / 6$ · región Ámsterdam
apt update && apt upgrade -y
adduser deploy && usermod -aG sudo deploy
ufw allow OpenSSH && ufw allow 80 && ufw allow 443 && ufw enable

Swap de 2 GB

Por qué: con 1 GB de RAM, n8n + Redis sin swap = el OOM-killer te mata n8n de madrugada. No es opcional.
fallocate -l 2G /swapfile && chmod 600 /swapfile
mkswap /swapfile && swapon /swapfile
echo '/swapfile none swap sw 0 0' >> /etc/fstab

Docker + n8n con SSL (Traefik)

Por qué Traefik: gestiona el certificado Let's Encrypt solo, sin tocar Nginx a mano.
curl -fsSL https://get.docker.com | sh
apt install -y docker-compose-plugin
# DNS: A  n8n.narosasp.com → IP. docker-compose vars clave:
#  N8N_HOST=n8n.narosasp.com  N8N_PROTOCOL=https
#  WEBHOOK_URL=https://n8n.narosasp.com/
#  N8N_ENCRYPTION_KEY=  · TZ=Europe/Madrid
#  restart: unless-stopped en todos los servicios
Crítico: guarda N8N_ENCRYPTION_KEY. Si la pierdes, todas las credenciales de n8n quedan ilegibles.
✅ Check: n8n.narosasp.com con candado válido y, tras reboot, vuelve solo.

Semana 2 · WhatsApp Cloud API

Webhook bidireccional verificado (no Baileys)

App de WhatsApp en Meta

Por qué Cloud API y no Baileys: Baileys (no oficial) se banea. Cloud API es oficial, con 1.000 conversaciones/mes gratis.
  • App Business → producto WhatsApp. Consigue Phone Number ID + token de System User permanente.

Webhook entrante + envío

Por qué: Meta hace GET para verificar (devuelves hub.challenge) y POST con cada mensaje. Suscribe el campo messages.
# Enviar respuesta:
POST graph.facebook.com/v20.0/{PHONE_ID}/messages
Authorization: Bearer {TOKEN}
{ "messaging_product":"whatsapp","to":"{wa_id}",
  "type":"text","text":{"body":"¡Hola! 🎈"} }
Ventana 24 h: fuera de ella solo plantillas aprobadas. Nada de mensajería en frío (banea).
✅ Check: entrante llega a n8n y sale respuesta.

Semana 3 · IA Claude + prompts

Conversa, cualifica, avisa

Claude API + límite de gasto

Por qué el tope primero: es el único coste que escala con tráfico. El cap mensual es tu red de seguridad.
  • Console → API key → Billing → límite mensual (ej. 20 €). Modelo Haiku por defecto; Sonnet si hace falta calidad.
  • Memoria por wa_id en Redis: conv:{wa_id} → array de turnos, reenviado en cada llamada.

Pegar los prompts en Claude / n8n

Por qué tres: uno define el carácter (system, se cachea), uno extrae datos+score, y uno dispara el aviso de lead caliente.
👉 Prompt 1 → casilla "system" de Claude
1 · Sistema (carácter)
Eres el asistente virtual de Narosa Sweet Party, empresa de globos y decoración de fiestas infantiles en Gràcia, Barcelona. TONO: cálido, cercano, alegre y profesional. Algún emoji con naturalidad (🎈🎉). Adáptate al tú/usted del cliente. OBJETIVO: ayudar a organizar la fiesta y recoger datos para un presupuesto. Pregunta de forma natural (1-2 cosas por mensaje, no como formulario): - Tipo de celebración (cumpleaños, baby shower, comunión, evento…) - Fecha y zona/barrio - Nº de niños/invitados y edad - Temática (unicornio, sirenas, dinosaurios, pastel…) - Presupuesto aproximado REGLAS: - Responde en el idioma del cliente (español o catalán). - Breve y claro; no abrumes. - Si no sabes algo (fecha exacta, precio cerrado), di que lo confirmas y preparas propuesta. - No inventes precios: da rangos. - Si es spam o ajeno a fiestas, despídete amable. - Con datos suficientes, ofrece el presupuesto y pide email o confirma WhatsApp.
👉 Prompt 2 → instrucciones del flujo en n8n
2 · Cualificación (datos + score)
Además del mensaje para el cliente, devuelve SIEMPRE al final este JSON (oculto al cliente): { "datos": {"tipo":"","fecha":"","zona":"","ninos":"","edad":"","tema":"","presupuesto":""}, "score": 0, "listo_presupuesto": false } Rellena solo lo que sepas; deja en blanco lo que falte. - score (0-100): interés y lo avanzado que está (datos completos + fecha cercana + presupuesto claro = más alto). - listo_presupuesto = true cuando tengas tipo, fecha, nº de niños y presupuesto.
👉 Prompt 3 → nodo de aviso (WhatsApp/Telegram a la dueña)
3 · Aviso de lead caliente 🔔
Cuando sea LEAD CALIENTE (listo_presupuesto = true, o score ≥ 75, o pide reservar/cerrar fecha), genera además este aviso para la dueña (no se lo muestres al cliente): 🔔 LEAD CALIENTE — [nombre o teléfono] Fiesta: [tipo] · [fecha] · [nº niños] Presupuesto: [importe] · Temática: [tema] Acción sugerida: [llamar hoy / enviar presupuesto]
✅ Check: conversación de 6-8 turnos coherente, JSON con score, aviso disparado en caliente.

Semana 4 · Remate + QA

Todo conectado y PROBADO antes de abrir

Instagram + Shopify + Email + Dashboard

  • Instagram Graph API (misma App Meta): DMs/comentarios reutilizan el flujo de Claude.
  • Shopify Admin API (app privada con token): precios/packs reales en presupuestos.
  • Resend: enviar el presupuesto en HTML.
  • Dashboard: sustituir datos demo por la query real a Sheets/Postgres.

QA + monitorización + backups

Por qué: un fallo el día 1 con un cliente real cuesta una venta. Rómpelo tú antes.
  • 5 pruebas: caliente, tibio, spam, fuera de zona, fecha ocupada. Revisar coste/conversación en Console.
  • Cron healthcheck cada 5 min → alerta a tu Telegram si cae algo. Snapshot semanal + export de workflows.
✅ Check final: 5 pruebas OK + costes bajo umbral + alertas → abrir al público.

Riesgos y notas para mí

  • Coste Claude: el único que escala → cap + prompt caching + Haiku por defecto.
  • Ventana 24 h WhatsApp: fuera de ella, solo plantillas aprobadas.
  • Verificación Meta: cuello de botella → lanzar el Día 0.
  • RAM 1 GB: vigilar; si aprieta, subir a 2 GB (12$) o externalizar Postgres.
  • N8N_ENCRYPTION_KEY: si se pierde, se pierden todas las credenciales guardadas.
  • Anti-baneo: nada de mensajería en frío masiva.
